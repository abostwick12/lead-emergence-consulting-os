# Phase 9 — Signals / SEE AGAIN plan

## Outcome

Phase 9 closes the V1 reinvention spiral by using the approved New Reality baseline to notice current change and explicitly renew inquiry. The Signals workspace is deliberately descriptive. It does not perform autonomous drift detection, predictive organizational modeling, causal diagnosis, or mature Pulse intelligence.

## Canonical acceptance map

| Document 07 acceptance | Implementation and proof |
|---|---|
| Signals describe observed change without autonomous diagnosis | Typed `signals` require source Evidence and reject diagnostic or causal language; UI labels Signal as weaker than Pattern; unit, browser, and database tests prove the boundary. |
| Trend comparisons use compatible data and correct versions | `descriptive_trends` validates the same indicator logical identity, definition, direction, unit, engagement, tenant, visibility, and time order before comparison. |
| Private coaching is excluded unless explicitly promoted | Signals and trends reject consultant-private, individual-private, coaching-shared, team-shared, and platform-restricted sources; no automatic promotion route exists. |
| Assumptions due for review can be surfaced | Append-oriented `assumption_review_schedules` and `current_assumptions_due` expose current effective assumptions with explicit review triggers and controlled human completion. |
| A Signal can become a new Observation or SEE REALITY re-entry item | `reenter_signal_as_observation` creates a new evidence-backed Observation, preserves the Signal, and creates an accepted human `REENTERS_AS` edge with audit evidence. |
| V1 never markets Signals as validated drift detection | Product copy, static verification, unit tests, browser tests, and database checks state and enforce the descriptive-only boundary. |

## Longitudinal experience

- New observations show source-grounded changes that may deserve attention.
- Trends compare only compatible measurements and display limitations beside the comparison.
- Assumptions to Revisit show the original statement, trigger, and due state rather than silently changing belief.
- Emerging Questions preserve inquiry before conclusion and retain Signal or Assumption context.
- Baseline shows the immutable New Reality reference used for SEE AGAIN.
- Re-entry is an explicit consultant action and leaves both the original Signal and resulting Observation inspectable.
- The client Progress context includes only deliberately shared longitudinal items and no mutation controls.

## Security and epistemic boundaries

- Every Signal is a typed tenant-owned domain object with an engagement, Evidence source, visibility scope, origin, and review state.
- Same-tenant composite foreign keys prevent cross-organization sources and relationships.
- Longitudinal intelligence excludes private coaching content before composition, not merely in the UI.
- AI-originated Signals or Emerging Questions must remain `SUGGESTED` pending human review.
- Direct authenticated inserts are revoked; controlled functions enforce authorized human actions.
- Signal is not Pattern, Trend is not causality, and re-entry is not validation.
- Baseline records remain immutable and time-specific.

## Verification

- Unit: descriptive-language boundary, controlled Signal vocabulary, indicator compatibility, and explicit re-entry context.
- Browser: consultant create/re-entry/review loop, five-area Signals workspace, client shared-only view, no client controls, narrow viewport, and fresh screenshots.
- Database: RLS, tenant-safe Evidence, privacy exclusion, compatible trends, due assumptions, immutable baseline projection, typed `REENTERS_AS`, original Signal preservation, and controlled writes.
- Static: `scripts/consulting-os/verify_phase9_signals_see_again.ps1` maps implementation evidence to the canonical criteria.
- Final acceptance: a separate complete-engagement audit traces DISCOVER → UNDERSTAND → NAME → DESIGN → CULTIVATE → MEASURE → INHABIT → SEE AGAIN and verifies Ministry-only distribution independence.
