# 2. Core Epistemic Principle

Meridian must never make organizational memory appear more certain than the evidence and review process justify.

SOURCE → EVIDENCE → OBSERVATION → PATTERN → ASSUMPTION / HYPOTHESIS → INTERPRETATION → INSIGHT / DIAGNOSIS → DECISION → OUTCOME → LEARNING

Each transition changes what may legitimately be claimed. Software may assist a transition; it may not silently perform it.

# 3. Canonical Epistemic Disciplines

## Presence before prescription

Do not begin with a solution and search backward for evidence.

## Listening before interpretation

Allow present experience to challenge inherited narratives.

## Observation before explanation

Record what happened separately from why it may have happened.

## Pattern before diagnosis

Recurrence warrants investigation, not causal certainty.

## Alternatives before closure

Material competing explanations remain visible until examined.

## Human judgment before organizational truth

AI may propose meaning; authorized humans validate conclusions and decisions.

## Purpose before measurement

Available data must not determine organizational value.

## Outcome before self-justification

Results may challenge the consultant model and organizational assumptions.

## Historical truth without permanence

A statement may have been valid and later become outdated without rewriting history.

## Privacy before convenience

Information existing in Meridian is not automatically legitimate input to every analysis.

# 4. Epistemic Classes

| Class | Meaning | Permitted claim |
| --- | --- | --- |
| SOURCE | Originating object/system. | This source exists in this context. |
| EVIDENCE | Inspectable material relevant to a claim. | This material records or contains X. |
| OBSERVATION | Something seen, heard, reported, or measured. | X occurred, was reported, or measured here. |
| SIGNAL | Potentially meaningful item. | X may warrant investigation. |
| PATTERN | Recurring or structurally related configuration. | X recurs or relates across observations. |
| ASSUMPTION | Belief treated as true in reasoning/design. | The organization operates as though X is true. |
| HYPOTHESIS | Testable proposed explanation/expectation. | X may explain or predict Y. |
| INTERPRETATION | Proposed meaning. | X may mean Y. |
| INSIGHT | Human-reviewed conclusion sufficiently supported for action. | Authorized reviewers judge X sufficiently supported. |
| DIAGNOSIS | Scoped evidence-supported account. | This explanation currently best accounts for scoped evidence. |
| DECISION | Authorized choice. | Authorized humans chose X for these reasons. |
| OUTCOME | Observed result. | X occurred relative to the goal/hypothesis. |
| LEARNING | Human-reviewed conclusion from outcomes. | The organization concluded X from outcomes/evidence. |

# 5. Origin Is Not Epistemic Status

| Origin | Meaning |
| --- | --- |
| HUMAN | Created by an authenticated human. |
| AI | Generated or materially synthesized by AI. |
| SYSTEM | Produced deterministically by platform/system logic. |
| IMPORTED | Brought from an external source/file/system. |

A human interpretation remains an interpretation. A system measurement remains source-bound evidence. AI origin never grants authority.

# 6. Canonical Review States

| State | Meaning |
| --- | --- |
| DRAFT | Not submitted for substantive review. |
| SUGGESTED | Candidate not yet accepted. |
| UNDER_REVIEW | Being evaluated against sources, alternatives, and context. |
| ACCEPTED | Accepted within its existing epistemic class. |
| VALIDATED | Authorized human review elevates an eligible synthesis to an organizational conclusion. |
| CHALLENGED | Contrary evidence/reasoning reopens the claim. |
| REJECTED | Explicitly declined but preserved. |
| SUPERSEDED | A newer operative formulation replaces it while history remains. |

Accepting a Pattern does not convert it into an Insight or Diagnosis.

# 7. Evidence and Provenance Model

## 7.1 Inspectable source requirement

| Source type | Minimum provenance target |
| --- | --- |
| Uploaded document | document id + page/section/paragraph or fragment. |
| Interview | interview id + participant context + timestamp/segment. |
| Meeting | meeting id + note/decision/action segment. |
| Assessment | instrument version + administration + item/dimension + response/aggregate. |
| Metric/system data | source system + metric/query definition + time window + record references. |
| Consultant observation | observer + time + context + direct statement. |
| Client-entered statement | author + time + workflow/context. |

## 7.2 Evidence immutability

Captured evidence is append-oriented. Corrections are recorded without silently rewriting historical evidence on which earlier reasoning depended.

## 7.3 Evidence quality

| Dimension | Question |
| --- | --- |
| DIRECTNESS | Primary/direct or secondhand? |
| RECENCY | How current relative to the question? |
| RELEVANCE | How directly does it bear on the claim? |
| COVERAGE | One incident/group or broad experience? |
| SOURCE RELIABILITY | What limitations are known? |
| CONTEXT COMPLETENESS | Is enough surrounding context retained? |

Do not collapse these dimensions into a pseudo-scientific certainty score without a defensible model.

# 8. Observation Rules

- Observations should be atomic enough to evaluate independently.

- Distinguish direct measurement, direct observation, stakeholder report, and extracted source statement.

- Preserve disagreement rather than averaging it away.

- Do not embed unexplained causal judgment.

- AI extraction may propose candidate Observations only with attached source fragments.

- Sensitive source visibility remains attached to derived material.

Poor: Managers are afraid to delegate.

Better: In 7 of 10 manager interviews, managers described seeking director approval for decisions assigned to managers by the documented role model.

# 9. Pattern Rules

| Component | Requirement |
| --- | --- |
| Statement | Describe recurrence/relationship without unsupported explanation. |
| Scope | Team, function, organization, engagement, period, etc. |
| Support | Multiple observations or clearly structural basis. |
| Contrary evidence | Material exceptions remain visible. |
| Recurrence basis | Why this is more than an isolated event. |
| Review state | Suggested, accepted, challenged, etc. |

Canonical guardrail: A pattern is evidence for investigation, not proof of causation.

# 10. Assumptions and Hypotheses

## 10.1 Assumption Register

| Field | Purpose |
| --- | --- |
| statement | What is being treated as true? |
| holder/scope | Who or what operates from it? |
| origin/history | Where did it arise? |
| supporting evidence | What supports it? |
| challenging evidence | What calls it into question? |
| status | UNTESTED / SUPPORTED / CHALLENGED / DISPROVEN / SUPERSEDED. |
| confidence rationale | Why is current confidence warranted? |
| influenced objects | Which decisions/designs depend on it? |
| review trigger | When/why should it be retested? |

## 10.2 Hypothesis discipline

A Hypothesis states a testable explanation or expectation and identifies evidence that would strengthen or weaken it. Prefer Hypothesis to premature Diagnosis while competing explanations remain plausible.

# 11. Interpretation, Insight, and Diagnosis

## 11.1 Interpretation

Multiple interpretations may coexist for the same Pattern. Meridian should make comparison and contrary evidence easy rather than forcing early convergence.

## 11.2 Validated Insight

An Insight is a human-reviewed conclusion judged sufficiently supported to inform action. Validation records reviewer, rationale, evidence, material contrary evidence, limitations, and date.

## 11.3 Diagnosis

| Required element | Requirement |
| --- | --- |
| Scope | Exactly what organizational condition is being explained. |
| Evidence base | Key evidence and observations. |
| Patterns | Patterns the Diagnosis accounts for. |
| Assumptions tested | Relevant assumptions and status. |
| Competing explanations | Material alternatives considered. |
| Reasoning | Why this explanation currently fits best. |
| Limitations | What remains uncertain/unobserved. |
| Validation | Authorized reviewer/date. |
| Revisit condition | What should reopen the Diagnosis. |

Diagnosis is organizational, not medical or psychological, and may not clinically classify individuals.

# 12. AI Trust Architecture

## 12.1 AI may

- Extract candidate evidence fragments and observations.

- Summarize documents, interviews, meetings, and assessments.

- Cluster similar observations and repeated language.

- Surface possible Patterns, Tensions, Hypotheses, Interpretations, Opportunities, or Alignment Conflicts.

- Compare stated and observed conditions.

- Retrieve source-grounded organizational memory.

- Draft meeting preparation and consulting artifacts from permission-eligible records.

- Surface potentially relevant contrary evidence.

## 12.2 AI may not autonomously

- Validate an Insight or Diagnosis.

- Make an organizational Decision.

- Create an accepted CAUSES relationship.

- Convert confidential coaching material into shared telemetry.

- Hide material disagreement to produce a cleaner narrative.

- Treat absence of evidence as evidence of absence.

- Promote suggested inferential objects without authorized review.

- Use inaccessible records.

## 12.3 AI suggestion contract

| Field | Rule |
| --- | --- |
| origin | AI. |
| process metadata | Enough for audit; output is not its own evidence. |
| generated_at | Timestamp. |
| task class | Structured purpose. |
| source set | Exact permission-eligible sources used. |
| citations | Claim/section-level references where practical. |
| review_status | Defaults to SUGGESTED. |
| confidence | Optional machine estimate; not probability of truth unless calibrated. |
| reviewer | Null until review. |
| derived human version | Human modification/validation links back rather than overwriting. |

# 13. Human Validation Workflow

SUGGESTION → REVIEW SOURCES + CONTRARY EVIDENCE → CHECK SCOPE + ALTERNATIVES → REJECT | MODIFY | VALIDATE | KEEP OPEN

Validation is a recorded organizational act. A reviewer should explain why a claim is sufficiently supported, not merely click Approve.

# 14. Confidence and Uncertainty

- Prefer qualitative confidence with rationale when useful: LOW / MODERATE / HIGH.

- Confidence attaches to a specific claim and scope, not an entire organization.

- AI confidence and human confidence are distinct.

- Consider evidence quality, coverage, consistency, contrary evidence, and alternatives.

- High confidence that a Pattern exists does not imply high confidence in its explanation.

- Preserve historical confidence as new evidence changes current confidence.

| Field | Meaning |
| --- | --- |
| confidence_level | NOT_ASSESSED / LOW / MODERATE / HIGH. |
| confidence_rationale | Why that level is warranted. |
| assessed_by | Human or AI origin. |
| assessed_at | Timestamp. |
| limitations | Known gaps or uncertainty. |

# 15. Contradiction, Dissent, and Minority Perspectives

Meridian should preserve disagreement because disagreement may itself be diagnostic.

- Do not discard minority perspectives merely because they are numerically smaller.

- Store contrary evidence alongside supporting evidence.

- Distinguish organizational consensus from leadership decision.

- AI synthesis must disclose material disagreement when relevant.

- A validated Insight may carry documented dissent and limitations.

- Retrieval should answer both what was decided and what credible alternatives were considered.

# 16. Causality and Attribution

| Relationship | Strength | Rule |
| --- | --- | --- |
| ASSOCIATED_WITH | Weak | Objects relate; no direction of effect claimed. |
| TEMPORAL SEQUENCE | Descriptive | One event occurred before another. |
| CONTRIBUTED_TO | Moderate | Authorized reviewers judge the source materially relevant among possible influences. |
| CAUSES | Strong | Exceptional assertion requiring human validation, evidence, alternatives, rationale. |
| VALUE HYPOTHESIS | Prospective | Expected causal logic stated before outcomes; never proof. |

AI may suggest causal hypotheses but may not autonomously establish CONTRIBUTED_TO or CAUSES as accepted truth.

# 17. Provenance Graph

Decision ← Insight/Diagnosis ← Interpretation ← Pattern/Tension ← Observation ← Evidence ← Source

Backward traceability answers why we believe or decided something. Forward traceability answers which decisions, roles, boundaries, interventions, capabilities, goals, or workflows depend on a given Assumption or Insight.

# 18. Citation and Source Display Rules

- Substantive AI synthesis for consultants should expose source references close to the claim.

- Client-facing synthesis may simplify presentation but must preserve a path to appropriate evidence where permissions allow.

- A citation identifies the actual source used, not a later summary.

- If a source is inaccessible due to privacy, the system must not reveal its content through labels or paraphrase.

- Anonymous assessment aggregates cite administration/dimension, not individual responses.

- Missing or unavailable sources reduce support rather than being silently ignored.

# 19. Retrieval Semantics

Meridian retrieval is not generic semantic search. It must consider tenancy, visibility, time, epistemic class, current versus historical validity, source quality, and the user's question.

| Question type | Retrieval behavior |
| --- | --- |
| What is true now? | Prefer currently effective validated records plus current evidence; distinguish unresolved claims. |
| Why did we do this? | Retrieve Decision plus informing Insights, Assumptions, evidence, authority, and historical context. |
| What did we believe then? | Use time-appropriate versions, not current replacements. |
| What are we seeing? | Prioritize observations, measurements, signals, and patterns before interpretations. |
| What might this mean? | Return candidate interpretations and alternatives, clearly labeled. |
| What did this produce? | Return outcomes, measurements, value hypotheses, evaluations, and learning without automatic causation. |
| What changed? | Compare versioned state/baselines and preserve intended versus emergent reality. |

## 19.1 Retrieval ranking principles

- Permission eligibility is a hard filter before relevance ranking.

- Time appropriateness precedes semantic similarity for historical questions.

- Validated records may rank above suggestions for conclusions, while alternatives remain available when requested.

- Primary evidence outranks summaries when proof/source is requested.

- Contrary evidence should be intentionally retrieved for high-stakes interpretation.

- Embeddings are discovery aids, not sources of truth.

# 20. Temporal Provenance and Versioning

- Preserve the version of each construct that was operative when a Decision was made.

- Do not rewrite historical reasoning when a construct is superseded.

- New evidence may challenge an old Insight without making the earlier decision irrational in its historical context.

- Distinguish current operative truth, historical truth, and superseded belief.

- The Emergent Organization Profile becomes a new baseline without erasing the Future State that preceded it.

- Historical queries use effective dates and version chains, not merely current rows.

# 21. Privacy-Aware Derivation

Derived knowledge inherits sensitivity from its sources unless an explicit authorized process creates a safe aggregate or shared derivative.

| Case | Rule |
| --- | --- |
| Private coaching note → AI summary | Summary remains within the same privacy boundary. |
| Multiple confidential interviews → organizational pattern | Only permitted if the engagement's confidentiality model allows aggregation and the derivative cannot expose protected individuals. |
| Anonymous assessment → aggregate | May be shared according to administration rules; individual responses remain protected. |
| Consultant-private hypothesis → client insight | Requires explicit promotion/validation into a client-visible object. |
| Restricted evidence → public/shared artifact | Prohibited unless an authorized declassification/redaction workflow exists. |

# 22. Meeting and Coaching Memory

- Meeting preparation may retrieve only records visible to all required processing context, subject to role-specific rules.

- Private consultant notes remain distinct from shared meeting notes.

- Coaching sessions may contain shared commitments while private reflections remain partitioned.

- A coaching-derived systemic observation must be explicitly promoted with appropriate abstraction and permission.

- Meridian should not surprise a participant by resurfacing confidential material in an unrelated context.

# 23. Assessment Epistemology

- Assessment responses are stakeholder evidence, not direct organizational diagnosis.

- Scores are measurements produced by a defined instrument/version; their meaning depends on the construct and scoring model.

- Qualitative responses may generate candidate observations or patterns with provenance.

- Anonymous or confidential administrations must preserve promised privacy in AI synthesis and retrieval.

- Comparisons across time require compatible instrument versions or an explicit normalization method.

- Do not describe Emergence 360 as scientifically validated unless validation work actually supports that claim.

# 24. Outcomes and Learning

Stage 5 must allow outcomes to challenge both organizational and consulting assumptions.

VALUE HYPOTHESIS → INTERVENTION / CAPABILITY → MEASUREMENT → OUTCOME → EVALUATION → LEARNING → SUSTAIN / IMPROVE / SCALE / STOP / REINVENT

- Outcome is not proof of cause.

- Good results do not automatically prove a healthy system.

- Harvest and Soil must both remain inspectable.

- Unexpected outcomes are first-class learning, not noise to be forced into the original hypothesis.

- Unsupported hypotheses remain valuable historical knowledge when preserved honestly.

# 25. SEE AGAIN and Assumption Retesting

SEE AGAIN reopens the organization's current model to evidence. Meridian should make it easy to identify the assumptions, decisions, and designs that underpin the present organization and ask whether they remain supported.

| Candidate classification | Epistemic treatment |
| --- | --- |
| NOISE | Do not promote without evidence of meaningful recurrence. |
| FRICTION | Local issue; may warrant improvement without reframing the organizational story. |
| ADAPTATION | Change within the current model. |
| EMERGENCE | Possible new capability/opportunity; investigate before naming. |
| DRIFT | Possible divergence between operative model and current reality; human review required. |
| REINVENTION | Conclusion that foundational assumptions no longer fit reality; requires authorized human judgment. |

# 26. Meridian Response Contract

When Meridian answers an organizational question, the response layer should make the epistemic structure legible rather than flattening everything into fluent prose.

| Response component | Requirement |
| --- | --- |
| Answer | Direct response appropriate to the user's question. |
| Status language | Use observed, suggested, interpreted, validated, decided, or measured accurately. |
| Sources | Expose appropriate citations/provenance. |
| Uncertainty | State material limitations or disagreement. |
| Time context | Clarify current vs historical when relevant. |
| Decision context | For 'why' questions, connect reasoning to the authorized Decision. |
| Privacy | Never imply inaccessible evidence or reveal protected source identity. |

# 27. Anti-Hallucination Invariants

- No substantive organizational claim without a retrievable supporting path or explicit labeling as a hypothesis/suggestion.

- No invented citations, source fragments, meeting content, assessment responses, or metrics.

- No merging two people, teams, engagements, or versions because semantic similarity is high.

- No current-state claim based solely on superseded records when current records exist.

- No causal language generated from temporal sequence alone.

- No private-source leakage through summaries, embeddings, citations, or generated examples.

- If evidence is insufficient, Meridian says so.

# 28. Minimum Acceptance Tests

1. AI suggests a Pattern from four observations and stores citations; it remains SUGGESTED until review.

1. A consultant rejects an AI Interpretation; later retrieval does not present it as organizational truth but can show it as rejected history.

1. Two competing Interpretations remain retrievable with their evidence and contrary evidence.

1. A validated Insight can be traced backward to source fragments and forward to Decisions it informed.

1. A superseded Assumption is returned for a historical query but not as the current operative assumption.

1. A private coaching note cannot appear in an executive meeting brief without explicit permitted promotion.

1. An anonymous assessment aggregate can support a Pattern without exposing individual responses.

1. An Outcome linked to an Intervention is described without causal language unless an accepted causal relationship exists.

1. A 'why did we do this?' query returns the historical Decision and time-appropriate Assumptions/Insights rather than today's replacements.

1. A high-similarity but cross-tenant source is excluded before retrieval ranking.

1. A missing source causes the system to qualify support rather than invent or silently substitute evidence.

1. A SEE AGAIN review can identify which current design decisions depend on an Assumption that has become CHALLENGED.

# 29. Worked Example — Delegated Authority

| Step | Epistemic record |
| --- | --- |
| Source | Interview transcripts, workflow records, decision-latency measurements. |
| Observation | Routine team decisions frequently require senior approval. |
| Pattern | Decision authority repeatedly escalates upward across several workflows. |
| Tension | Stated empowerment may conflict with observed approval structure. |
| Assumption | Senior approval protects decision quality. |
| Hypothesis | Centralized approval may persist because oversight is equated with quality. |
| Interpretation | The constraint may be authority architecture rather than lack of initiative. |
| Insight | After human review, selected routine decisions appear suitable for delegation if boundaries and capability are explicit. |
| Decision | Delegate defined decision categories to team leads. |
| Value Hypothesis | Latency should fall without degrading quality if authority, capability, and boundaries move together. |
| Outcome | Measured results after implementation. |
| Learning | Human-reviewed conclusion about what those outcomes taught. |
| New Reality | Profile records how authority actually operates after normalization. |
| See Again | Later evidence retests the assumptions supporting the model. |

# 30. Definition of Meridian Trustworthiness

Meridian is trustworthy when a user can distinguish evidence from interpretation, see who or what produced a claim, inspect the sources appropriate to their permissions, understand the uncertainty and historical context, trace conclusions into decisions, and revisit those conclusions when reality changes.

Know what we observed. Know what we inferred. Know what we accepted. Know why we decided. Know what happened. Know what changed.
